日期：2026-10-22。范围：本仓库 11 个 Skill 的正文、发现描述、必要参考与评测场景。未同步任何 Agent 安装目录，未在本仓库提交或推送。

以下各节记录首次正文精修的快照与实测。随后用户明确 `decision-to-spec` 应作为上游 `to-spec` 的具体入口，该 Skill 和相关描述已再次调整；原快照与 20 条选择模拟不能替代新版本验证。后续结果另见文末“to-spec 入口定位修正”。

## 这次改动解决什么

| 范围 | 实质变化 |
| --- | --- |

十个个人版的 agents/openai.yaml 未修改；四个原有仅手动入口的标志与策略保留。SKILL.md 总字符数相对 HEAD 从 46,195 到 24,460（约减少 47%，含 frontmatter）；另有两个按需模板。长度变化不作为质量结论。

## to-spec 入口定位修正

用户明确：decision-to-spec 原本就是调用上游 to-spec 的具体入口。首次精修将其过度收窄成同步器；原 decision-scope 只证明轻量同步正确，不能证明完整规格主流程符合这一意图。

修正后的主路径为：整理讨论与决定 → 实际读取并执行当前 to-spec → 适配项目文档与实质取舍 ADR → 复核一致性。已有完整规格的小改动可走轻量同步；完整规格路径不再只建议用户另跑上游。上游默认 issue 发布适配为本入口既有的本地文档交付；只有明确授权 issue 目标时才执行发布。新测试边界仍需确认，已有有效决定直接复用。

本轮同时更新入口 description、UI 简述、README 和治理参考；调用策略未改变，未修改任何已安装 Skill 或上游副本。核对到的共享源与仓库上游快照内容哈希相同：c73a2250beac0479e384f5466e834bb54ce6e30b7f8705e9999ba840d9d59b36。新入口正文哈希：b706b34af1a8f92eaf920d4c39eb688c86eeaac118a1f44a64c26d7aa2e46d04。

独立执行者 /root/verify_spec_entry 只接收两个请求、真实 Skill 与原始仓库资料，不读取期望或此前结论：

| 场景 | 实际行为与产物 | 复核 |
| --- | --- | --- |
| spec-entry | 读取共享源 to-spec 并按其章节生成完整规格；保持导出范围，复用已确认公开入口测试边界，界面位置保留未决 | 只写 docs/spec.md 与 README；未重新询问、未运行测试、未配置 tracker 或发布；产物检查及链接检查通过 |
| decision-scope 回归 | 走轻量同步，按钮文案更新规格，缓存取舍建立一个 ADR 并更新索引 | ADR 含备选优势、拒绝理由和代价；只改预期文档，产物检查通过 |

这里的上游执行由同一 Agent 读取并应用真实正文完成，没有专用 Skill 调用工具，不虚报原生嵌套调用。未覆盖目标 Agent 安装后的自动发现或原生调用能力。
