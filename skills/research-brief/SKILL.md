# 调研任务书

交付一份不依赖当前聊天也能执行、结果可以复核的调查委托。完成条件是任务书的范围、问题、已知事实、证据标准、交付物和接收条件清楚；**用户是否派发、派给谁，不是完成任务书的前置条件。**

## 1. 判断委托是否有价值

先读取项目已有的调研政策和最接近的资料。没有项目规则时，判断问题是否同时满足：

- 无法通过有界查阅快速可靠地回答；
- 会影响设计、正确性、许可证、迁移或性能等实际决定；
- 能给出独立可执行的范围、资料入口和判定标准。

可以核对项目入口、目标代码或一个主要来源，确认问题尚未解决、版本和路径有效。**这属于准备任务书的有界核实，不是提前完成整项受托调查。** 已有充分上下文时不为了过关再固定搜索一轮。

不值得委托时，说明直接查阅更合适；用户明确仍需任务书时按其需要提供简版，不把一般判断当成拒绝用户的硬门槛。用户只要求直接研究时使用实际研究流程，不擅自改成交任务书。需要用户体验才能决定的交互不伪装成独立调查，可建议其主动使用交互原型流程。

## 2. 写成独立可执行的任务

遵循项目语言、目录和编号制度；没有指定落盘时可直接交付完整正文。任务书包括下列信息，简单任务可合并段落：

| 信息 | 要写清 |
| --- | --- |
| 决策问题 | 为什么查，调查结果将支持哪个决定；不预设应采纳的方案 |
| 已核实事实 | 当前版本、约束、相关代码/配置/资料入口和可复核来源；用户提供但未核实的前提单独标明 |
| 调研问题 | `Q1/Q2/...`；每题包含要证明什么、搜索线索、何时算答完 |
| 范围与非目标 | 模块、版本、候选、环境及不应替项目决定的事项 |
| 证据标准 | 高影响结论优先本地实物、官方源码、规范或第一方资料；第三方资料可作线索，不冒充已核实事实 |
| 产出与限制 | 逐题结论、证据定位、适用条件、风险、无法确认项；事实、推断和建议分开 |
| 执行与交付 | 默认只读，不改代码；报告路径/命名、索引要求、结果回报方式和接收条件 |

比较候选时使用相同维度，例如兼容性、维护边界、成本和验证方法，不强塞与问题无关的比较表。涉及公式、坐标、尺寸、解析或渲染时要求用代表性样本验算；没有样本时要求给出验证计划，不能暗示适用性已经得到证明。

不能编造路径、行号、源码结论或负责人；无法核实的材料写成待确认前提。证据冲突时要求保留双方来源与适用条件，不让受托者猜测。

## 3. 检查并交付

用“接收者只看到任务书”的视角检查：能否找到资料、逐题作答、识别禁区、保存结果；接收者能否用同样标准判断答复是否足够。缺少会改变研究方向的关键输入时，只澄清该缺项，其他内容先完成。

任务书自身已是交接材料，不再附一份重复交接表。交付后结束本任务，不自动调用 `research`、发送给其他 Agent 或等待研究结果。用户之后明确授权执行时，再采用 `research` 或约定流程；调查建议需经采纳才能通过 `decision-to-spec` 进入正式规格，实质取舍记录到 ADR。

不要把任务书写成最终调研报告，也不要把“已交付任务书”写成“研究完成”或“方案已采纳”。
