# 仓库文档初始化

以 MTP 文档治理为默认范式，复现文件角色、主来源关系与维护责任，再根据目标仓库本地化。参考项目提供机制，不提供可以直接复制的产品内容或研究分类。

## 1. 选择模式并读取事实

- `full-governance`：用户要求初始化/复现治理结构时的默认模式，创建有实际入口内容的完整骨架。已有少量 Markdown 不使任务自动降为只读。
- `adopt-existing`：用户要求接管或补强已有体系时，保留其目录和命名，只补缺口。
- `plan-only`：用户明确只要盘点、提案或暂不写入时，只交映射与差距。

读取项目及父目录指令、README、领域/术语文档、构建测试入口、现有文档、`.gitignore` 和工作区状态；按需查源码、部署或票据入口，确认领域、交付方式与私有边界。

初始化授权允许创建/补强文档，不包括产品代码、部署、提交或推送。保留用户未提交改动；删除、覆盖、批量迁移历史或移动私有资料需有对应授权与旧新路径映射。

## 2. 按信息用途确定主来源

区分现行决定、术语、规格、实质取舍 ADR、研究、工作流、计划/票据、执行证据、设计资产、历史与私有材料。每类现行信息指定唯一主要来源，其他入口只链接或摘要。

Research 分类从仓库实际稳定领域推导，不照搬 `ENG/CODE/ECO/ARC/UX` 或 `SYS/CODE/ECO/ARC/UX`。能说明实际研究对象、反例边界和编号责任才建立类别，事实不足则标为待确认。

主题、ADR 和普通文件名使用中文，专有名词与工具固定文件名保留原文；已有路径不为语言统一擅自迁移。Research 的编号、任务书/报告配对、交付/审阅/采纳状态按 [治理基线](references/governance-baseline.md) 本地化。

大范围写入前建立简短映射：信息类型 → 目标主来源 → 新建/补强/保留 → 未决点。已获授权且无冲突时映射仅作内部检查，无需再请用户批准。权威来源、公开范围或迁移边界不清时仅暂停相关动作，继续可独立完成的部分。

## 3. 创建或补强入口

执行初始化时读取两份互补参考：

- [governance-baseline.md](references/governance-baseline.md)：文件角色、各入口最低内容、命名与 Skill 路由。
- [reproduction-manifest.md](references/reproduction-manifest.md)：根文件、Docs、领域目录与工作台的必选/按需清单。

沿用已有 `Docs/`、`docs/` 或等价路径，不另建平行体系。完整模式按清单建立入口；需要预留但尚未启用的模块用 README 写明启用条件，不适用模块登记原因，不创建空目录、假报告或假决定。

`AGENTS.md` 保留短而可执行的约束、阅读顺序和任务路由；详细模板留在对应文档。引用 Skill 前核对是否可发现及调用策略，手动入口只写主动使用建议；不存在的能力写职责或项目替代流程，不虚构安装依赖。参考路由不是所有任务的强制流水线。

正式文档与 `.scratch` 执行材料分层。启用票据体系时读取 [ticket-governance.md](references/ticket-governance.md)，保留单票状态唯一来源、依赖、Checklist、人工验收与封存边界。需要逐项复核时再读 [bootstrap-checklist.md](references/bootstrap-checklist.md)。

许可证、版权主体、维护负责人或发布版本缺失时记录待补，不编造。研究建议、聊天和原型未获采纳前不写成决定；测试输出不升级为真实环境验收。

参考私有项目时只使用已获授权的治理机制，不复制个人姓名、联系方式、账号、设备、密钥、私有业务正文或本机绝对路径。不改变目标仓库已有的公开/私有边界。

## 4. 核对并交付

复核新增/变更入口的链接、编号、状态、主要来源、忽略规则与 Skill 路由；有项目检查命令则运行相关最小检查，否则明确是静态核对。不要把文档骨架建立说成产品、测试或部署完成。

`full-governance` 必须写初始化记录；其他模式按用户要求交付。记录包含：模式与基线日期、实际本地分类及依据、文件动作（新建/补强/保留/不适用/待补）、主来源、未启用条件、检查证据和后续责任。不能只交目录树。

报告优先放目标仓库既有迁移/记录入口并登记；无合适位置时用 `.scratch/reports/repository-docs-bootstrap/<YYYY-MM-DD>-<仓库名>.md`，已有 Docs 入口中登记该位置。记录只保存目标仓库事实与机制来源，不复制正文和隐私。

后续纯链接/状态审计使用 `docs-integrity-audit`；已确认决定同步使用 `decision-to-spec`。本 Skill 不借初始化自动开展研究、全面审计或阶段验收。
