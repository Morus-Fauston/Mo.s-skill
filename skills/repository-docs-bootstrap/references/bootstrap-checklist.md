# 文档初始化检查表

这份检查表只在初始化或大范围补强时读取。它用于收集证据和防止漏项，不规定每个仓库必须采用同一目录。

## 事实采集

- [ ] 根目录、父目录和项目级 `AGENTS.md` 已读取，冲突按更具体范围处理。
- [ ] 根 README、领域术语/上下文、构建、测试、部署和包管理入口已定位。
- [ ] `git status --short`、`.gitignore` 和现有本地私有材料边界已记录。
- [ ] 源码、测试和资源的主要模块已用实际目录名记录。
- [ ] 当前文档入口、历史/归档目录和未索引 Markdown 已区分。
- [ ] 已按 [复现清单](reproduction-manifest.md) 判断正式记录、计划、会议、产品域、期次 `goals/`、证据二进制池和文档治理记录是否适用。
- [ ] 现有修改未被覆盖；重命名或移动候选有旧路径、目标路径和引用清单。
- [ ] 默认治理语言已确认；ADR、Research 主题和普通文件名中的非专有词为中文。

## 分类判定

对每个候选类别回答：

1. 它回答什么稳定问题？
2. 目标仓库中有哪些真实文件或模块属于它？
3. 哪些相似材料明确不属于它？
4. 谁在何时更新它，状态由谁确认？
5. 它是否需要编号、配对、索引或历史迁移？

没有实际对象、反例边界或维护责任的类别不建立。研究前缀只表达研究对象，不表达版本号、讨论轮次、Agent 名称或任务来源。任务书与报告需要配对时共用类别和序号；没有任务书的历史报告不补造空任务书。

研究命名专项检查：

- [ ] `Research/README.md` 已列出每个类别的中文名称、适用范围、正例和反例。
- [ ] 类别内编号从现有最大号继续递增，不复用旧号，不按版本或 Agent 编号。
- [ ] 任务书和报告使用同一类别与序号；文件主题为中文，只有库名、产品名、协议名、API 名等专有名词保留原文。
- [ ] 文件名未使用 `report`、`task`、`research`、`decision` 等通用英文后缀或主题词。
- [ ] 索引分开登记交付、审阅、采纳和部分采纳，报告存在不等于结论已采纳。

## 最小文件映射

| 文件或入口 | 必须回答的问题 |
| --- | --- |
| `AGENTS.md` | Agent 开工前读什么？哪些规则可验证？何时必须停下等人？ |
| 术语表/`CONTEXT.md` | 哪些词有正式含义？哪些边界不能混用？ |
| 文档总入口 | 当前依据从哪里开始？历史和私有材料在哪里？ |
| 当前决策/规格 | 当前做什么、为什么、范围和验收边界是什么？ |
| ADR | 哪些决定存在实质取舍，接受了什么代价，为什么放弃备选？ |
| Research 入口 | 研究对象、编号、交付/审阅/采纳状态和证据在哪里？ |
| 工作流 | 反复执行的输入、输出、责任和人工关口是什么？ |
| 执行台账/票据 | 当前工作如何关联范围、依赖和证据？ |
| 验证反馈 | 哪些是一次运行的原始证据，哪些只是摘要？ |
| 历史/迁移/归档 | 旧材料如何追溯，为什么不再作为当前依据？ |

## Agent 工作流写法

在 `AGENTS.md` 里只写仓库真正需要的路由。用“当前问题 -> 主 Skill -> 必要转交 -> 人工关口”的形式表达，例如：

```text
方向未定 -> grilling/think -> 用户确认 -> decision-to-spec
需要独立委托材料 -> research-brief -> 用户自行决定是否派发
关键事实不清 -> research 或等价调查 -> 审阅并确认采纳 -> decision-to-spec
单改动验证层/证据存疑 -> evidence-based-validation
明确阶段验收 -> phase-acceptance（复用已有有效证据）
代码审查 -> check 或等价审查
文档迁移/断链 -> docs-integrity-audit -> 发现缺少已确认落点时 decision-to-spec
```

- [ ] 已复制并按项目修改 [治理基线中的 Skill 工作流参考段落](governance-baseline.md#agentsmd-skill-工作流参考段落)。
- [ ] 参考段落没有被改成强制串行流水线，且保留用户确认、真实环境和 Git 写入关口。

不要把“创建任务书”“报告已交付”“测试通过”“用户确认采纳”“真实环境通过”压缩成一个完成状态。涉及产品取舍、外部权限、真实设备、生产环境、版本号或 Git 写入时，写明确认人或人工关口。

## 检查结果

- 当前入口：逐个打开或静态确认目标存在。
- Markdown 链接：至少检查新增和受影响文件；无法全量解析时标明抽样。
- 状态：区分未开始、进行中、已交付、待审阅、已审阅、已采纳、部分采纳、未采纳、待人工等实际词义。
- 主来源：每条现行规则只有一个主要来源，派生文档使用链接或短摘要。
- 历史：旧路径、旧编号和历史结论保留在迁移/归档边界内，不混入当前入口。
- Git：只报告工作区事实，不执行 `add`、commit 或 push。
