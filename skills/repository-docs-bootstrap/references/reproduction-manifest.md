# Mo's 文档治理复现清单

这份清单以 MTP 的文档治理为主范式，把其他项目中可复用的补充机制整理成可执行的初始化决策。它不是要求每个仓库复制所有目录，而是要求 Agent 对每个角色给出“新建、补强、保留、不适用或待负责人补充”的结论，并把结论写入初始化报告。

## 复现原则

1. 先保留目标仓库已有的大小写、目录语言和公开边界；`Docs/`、`docs/` 和其他等价入口不得因为模板偏好批量改名。
2. 根入口、正式文档、票据、原始证据、历史材料和本机缓存分层；每类当前事实只有一个主要来源。
3. MTP 的根文件、`Docs` 分层、Research 索引、期次票据和证据目录是默认骨架；LICO 的 `records/`、`meetings/`、`plans/`，其他项目的产品域/来源分区，以及 MTP.NET 原型记录中的分层验证表只能按目标仓库事实作为补充模块。
4. `.scratch` 默认是本地私有工作台。只有仓库明确需要共享或公开执行材料时，才改变 `.gitignore` 边界，并在报告中记录负责人和原因。
5. 私有参考项目只提供机制层启发。输出中不得出现个人姓名、联系方式、账户、设备信息、密钥、私有业务数据或本机绝对路径；项目名可以作为来源标签保留。

## 根目录清单

| 角色 | 默认路径 | 默认动作 | 何时建立或补强 |
| --- | --- | --- | --- |
| 项目入口 | `README.md` | 保留并补强 | 始终建立，链接运行、当前状态、文档和 Agent 入口 |
| Agent 规则 | `AGENTS.md` | 新建或补强 | 始终建立；只放可执行硬约束和 Skill 路由 |
| 术语与上下文 | `CONTEXT.md` | 新建或补强 | 有稳定领域词汇、模块边界或不可混淆概念时建立 |
| 忽略边界 | `.gitignore` | 保留并补强 | 始终检查 `.scratch`、运行状态、密钥、构建物和私有 Docs |
| 版本记录 | `CHANGELOG.md`、`CHANGELOG.txt` | 按需建立或保持双格式 | 仓库已有发布记录、用户要求版本记录或发布流程依赖它们时 |
| 许可证 | `LICENSE` | 保留或登记待补 | 不猜版权主体、年份或许可证文本；缺失只记录责任人 |

## MTP 默认全局 Docs 清单

以下目录位于现有 `Docs/`、`docs/` 或等价文档根目录。完整治理模式建立核心入口 `README.md`；按需类别达到启用条件才建立。需要预留但尚未启用的类别用 README 说明启用条件；不适用类别只在初始化清单登记，不创建目录。

| 入口 | 作用 | 默认级别 |
| --- | --- | --- |
| `README.md` | 总导航、主来源、私有/历史边界 | 核心 |
| `当前决策/` | 已确认范围、产品定义、规格入口和决策落点 | 核心 |
| `ADR/` | 存在实质取舍的架构或产品决定 | 核心 |
| `Research/` | 任务书、报告、交付/审阅/采纳登记 | 核心 |
| `工作流/` | 开发、调研、验证、发布、手动交接和文档治理 | 核心 |
| `agents/` | 领域约定、票据规范、交接规则 | 核心（使用 Agent 时） |
| `验证反馈/` | 可追溯运行证据、人工研判和验证摘要 | 有真实环境或阶段验收时 |
| `待办与预案/` | 已确认方向的执行待办、风险和行动预案 | 有阶段计划或遗留风险时 |
| `设计资产/` | 原型、参考图、模板、流程图和其他设计工件 | 有设计工件时 |
| `使用手册/` | 开发、验收、工具和人工操作手册 | 有重复操作或人工验收时 |
| `历史规格/`、`历史与归档/`、`归档/` | 已替代或停止使用的材料 | 有历史材料时 |
| `迁移与记录/` | 路径迁移、去重、索引修复和治理变更证据 | 发生迁移或大范围初始化时 |
| `参考资料/` | 外部资料清单和只读参考 | 有外部参考且需留痕时 |

以下是 MTP 之外的可选扩展，不默认创建：

| 入口 | 作用 | 启用条件 |
| --- | --- | --- |
| `records/` | 决策总表、决策落点、未定事项、待办表 | 正式治理记录数量和责任需要单独登记时 |
| `plans/` | 阶段、角色、首期或分期计划 | 计划不适合放在当前决策时 |
| `meetings/` | 会前材料、会议归档、决议转录和确认记录 | 有正式会议决策且需要会议档案时 |

MTP.NET 式原型或平台验证不另设产品目录：把“结论、已执行验证、证据层级、已知限制和后续项”放进 `验证反馈/` 或对应产品域的 `验收与发布/`，并明确构建、自动化、进程/端到端、真实 Windows/设备和人工确认各自能证明什么。原型记录不能替代正式 ADR、规格或票据状态。

## 独立产品域或维护域清单

当仓库有多个能独立维护、验收或发布的产品域时，在全局 Docs 下建立 `<产品域>/README.md`。每个域按事实选择下列入口：

```text
Docs/<产品域>/
├── README.md
├── 当前决策/       # 可选：域内产品口径和决策落点
├── 规格/           # 需求、用例、流程、状态机、非功能需求
├── ADR/            # 域内架构取舍
├── 架构与设计/     # 工程规划、原型、视觉和实现边界
├── 问题与记录/     # 缺陷、健康检查、讨论和同步记录
├── 验收与发布/     # 沙盒、真机、环境、版本和发布操作手册
├── 商务与合作/     # 只有确有外部合作或合同草案时建立
└── 历史与归档/     # 域内历史材料
```

域 README 必须说明：域的责任边界、当前主来源、与全局决策/Research/票据的关系、维护责任和私有材料边界。不要把不同域的 ADR、规格和验收资料混成一个无主目录。

## `.scratch` 票据工作台清单

启用本地票据时，至少建立总入口和一个实际使用的期次/功能目录：

```text
.scratch/
├── README.md
├── <期次或功能主题>/
│   ├── README.md
│   ├── issues/       # 单票状态唯一来源
│   ├── evidence/     # 按票号或验证主题保存运行批次
│   ├── work/         # 可再生中间文件
│   ├── goals/        # 启动文本或阶段目标，不与 issues 混用（按需）
│   └── research/     # 该期临时研究（按需）
├── research/         # 跨期下载缓存和参考材料（按需）
├── tool-cache/       # 本机探针和工具缓存（按需）
├── 证据二进制池/      # 按 SHA-256 复用的大型二进制（按需）
└── 文档治理/          # 迁移清单、去重记录、布局核查（发生治理变更时）
```

期次 README 只导航目标、票据、依赖、证据和正式文档，不复制实时状态。票据正文、状态机、证据目录和交接规则必须遵循 [ticket-governance.md](ticket-governance.md)。原始日志、截图、JSON 和二进制不因整理改写；迁移时保留旧路径、新路径和哈希。没有实际材料时不要制造假的证据批次或空票据。

## 初始化报告必须回答

- 根文件、全局 Docs、产品域 Docs 和 `.scratch` 哪些角色已新建、补强、保留、不适用或待负责人补充；
- 每个本地 Research 类别的事实依据、正例、反例、编号起点和维护责任；
- 每类当前信息的唯一主来源，以及票据、证据、历史和缓存的派生关系；
- 未启用目录的启用条件、私有公开边界、真实环境/人工验收的未检查范围；
- 参考项目只提供的机制、没有复制的产品内容，以及后续责任人。
- 隐私检查结果：未写入个人信息、凭据、设备信息、私有业务内容或本机绝对路径。
