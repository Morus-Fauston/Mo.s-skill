# Discernment Nudge

帮助用户在行动前看见答案中值得核对的事实、推理前提或缺失背景。产物最多是一段可跳过的结尾提醒，不是再做一轮评审，也不是让用户为每个答案完成作业。

**来源与改动说明：本文件基于 Anthropic 的 `discernment-nudge` 改写，采用 Apache-2.0。**本地化引导语与问题、整理条件顺序，保留原有触发意图、优先排除和频次限制；不再强制固定英文引导句。许可和来源说明见 [UPSTREAM.md](UPSTREAM.md)。

## 先检查是否应当省略

下面的排除条件优先于后面的适用场景。符合任一项就不追加提醒，即使答案含数字、研究或多步推理。

| 情况 | 处理 |
| --- | --- |
| 同一对话已经出现过这种提醒 | 后续轮次不再追加，不因新主题、再次加载或措辞变化重新计算 |
| 用户已经要求核查、引用来源、指出不确定性或审阅 | 在主答案里完成核查、引用和风险说明，不再建议用户核查刚核查过的内容 |
| 用户请你检查其材料、推理或方案是否正确 | 答案本身就是判断步骤；真正缺失的信息在相应位置直接说明或提问，不移成结尾作业 |
| 用户只要简短版本、不需要附加提示，或明确会自行核查 | 尊重其选择，回答后停止 |
| 用户提供内容，只要求总结、排版、转换、拼装或提取事项 | 忠实处理原材料，不再问用户确认原材料的假设；若无法忠实表达，直接在答案内说明 |
| 纯教育、定义或比较，只为理解而非作现实选择 | 不追加；健康、法律、金融等领域的解释也不因领域名称而自动触发 |
| 闲聊、创意写作、一般头脑风暴 | 用户自己判断表达与创意，不增加事实核查仪式 |
| 交付用户会执行的代码 | 运行代码是验证路径，不为代码本身追加提醒；架构建议不属于此项 |
| 用户只是问看法或个人评价 | 观点不是权威事实，不为“验证看法”追加问题；依赖未核实事实的部分直接在主答案中限定 |

只有真正出现可行动的具体建议，才可能从纯解释或头脑风暴转入适用场景。对用户给出的数据作趋势、因果或显著性解释，也不同于仅替用户整理材料。

同一对话最多提醒一次，不要求在第一轮出现。只依据当前可见的对话判断，不为频次读取私人历史、写日志／记忆、创建任务或调用新工具；不因拿不到额外记录而要求用户证明自己没被提醒。

没有具体值得复核的内容时保持安静，**不输出空标题，也不解释“本次省略提醒”**。

## 再判断提醒是否有价值

只有未命中排除条件，且下面内容中有用户行动前值得检查的具体点，才追加提醒：

- 预算、工期、成本、概率或效果等估算，缺少用户场景中的关键依据。
- 会影响业务、财务、职业、关系等现实选择的建议，结果依赖尚未给出的背景。
- 用户可能据此作决定、写报告或对外引用的事实主张，而不是仅为了解知识。
- 多步推理的前提若不成立，结论会随之改变。
- 你替用户解读数据或研究，作出趋势、因果、比较或方案判断。
- 你起草用户将实际使用的目标、计划、提案等工件，其中含你补出的选择或假设。

提醒不能替代本应完成的事实检查、安全说明或不确定性披露。已知证据不足、来源矛盾或结论不稳，先在主答案对应位置明说，不能藏成一句可选追问。

## 写成用户可以直接问回来的问题

追加 **2 至 3 个短问题**，每个只检查一个具体点。凑不出两个有用的问题时，不为满足数量写空泛问题。

- 用用户的第一人称和口吻写成问句，用户可以直接复制发给你；不要变成你向用户盘问的必填问题。
- 每个问题必须关联本次答案中的数字、命名步骤、建议、论证前提或未提供的条件。
- 可以请你补核事实、解释推理，或说明缺少某个背景会如何改变结论；不要求用户自己完成全部调查。
- 每个问题通常不超过约 120 个字符，避免在问题里再塞一段推导。
- “能再检查一下吗”“这些可靠吗”这类没有具体对象的问题没有帮助，不使用。

## 按对话语言呈现

遵循当前有效指令和用户明确的输出语言要求；未指定时跟随当前对话的自然语言。正文、引导句和问题保持同一种适用语言，不因为此 Skill 用中文编写就强制所有会话中文。

引导句可以简短自然地提示后面的追问，不固定英文，也不另设必须逐字照抄的中文口号。不同时重复中英文两套提示，不在换语言时重新发送已经给过的提醒。

先完整回答用户，再空一行，追加一行普通引导语与问题列表。引导语不用 Markdown 标题、粗体、引用框、HTML 或表情；问题用普通 `-` 列表。提醒应容易跳过，不冒充警告或确认关口。

中文形式示例，仅在确实针对当前答案时使用：

```text
还有几点可以再核对：
- 我这次的三周期限，是基于哪些尚未确认的工作量？
- 如果我需要支持离线使用，刚才的方案排序会怎样变化？
```

英文形式示例，不是固定结尾，也不要与中文示例一起输出：

```text
Questions I could explore next:
- How would my existing support costs change the proposed budget?
- Which assumption in my rollout plan would most affect the two-week estimate?
```

提醒之后不再附“要不要我继续”“随时告诉我”等邀约、解释或推销。这些问题只是用户可选的追问，不调用其他 Skill、工具或子代理，不执行新的调查，也不写文件来记录提醒。
