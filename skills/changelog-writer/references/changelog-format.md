# Changelog 格式详细规范

本文件是 SKILL.md 的补充参考，包含双文件体系的完整格式要求。

## CHANGELOG.md 完整格式

```markdown
## vX.Y.Z (YYYY-MM-DD HH:mm)

### 分类标题（修复 / 新增 / 调整 / 架构改进 / 体验优化 / 核心重构 / 技术 / 文档）

- **关键词**：一句话描述改了什么、为什么改
  - 子要点（可选，用于多步骤/多状态说明）
  - 子要点

### 文件变更表（功能版本或主版本附带；PATCH/预发布版本可省略）

| 文件 | 变更 |
|:-----|:------|
| `path/File.py` | **新增** — 说明 |
| `path/File2.py` | 修改了什么 |
```

### 写作要点

- 每条以 **加粗关键词** 开头，后接中文冒号 `：`
- 修复类条目写清「现象 → 根因 → 修复方案」
- 功能版本（MINOR）和主版本（MAJOR）附文件变更表；补丁版本（PATCH）和预发布版本可省略
- 里程碑版本可加「整体回顾」段落，用表格总结阶段演进
- 条目倒序排列，最新版本在文件最顶部
- 用 `---` 分隔不同版本条目

## CHANGELOG.txt 完整格式

```
vX.Y.Z (YYYY-MM-DD HH:mm)
  分类: 一句话压缩总结
  - 要点1
  - 要点2
```

### 写作要点

- 能一行说完就一行，多项用 `/` 或 `|` 分隔
- 用缩进（2 空格）表示子项
- 大段落用 `====` 分隔线
- 纯文本，无 Markdown 格式

## 版本号规则

- **三段基础版本号** `MAJOR.MINOR.PATCH`
  - PATCH（第三位）：向后兼容的缺陷修复（`0.2.0 → 0.2.1`）
  - MINOR（第二位）：向后兼容的新增功能（`0.2.x → 0.3.0`）
  - MAJOR（第一位）：不兼容的公开接口、行为或数据格式变更（`0.x.x → 1.0.0`）
- **预发布版本**：在基础版本后加连字符和标识，例如 `0.3.0-alpha.1`、`0.3.0-beta.1`、`0.3.0-rc.1`。
  - `alpha`：早期试验；`beta`：功能基本完成，等待试用；`rc`：候选发布版。
  - 相同阶段递增末尾数字，例如 `0.3.0-rc.1 → 0.3.0-rc.2`。
  - 正式发布时移除预发布后缀，例如 `0.3.0-rc.2 → 0.3.0`。

已经发布的版本不得修改。发现修复时发布下一个 PATCH 版本，例如 `0.3.2 → 0.3.3`。Git 标签可使用社区常见的 `v` 前缀，例如 `v0.3.3`，但版本本体是 `0.3.3`。

## 分类标题速查

| 分类 | 适用场景 |
|:-----|:---------|
| 修复 | Bug 修复 |
| 新增 | 新功能/新文件 |
| 调整 | 行为变更、入口迁移 |
| 架构改进 | 重构、模块拆分、设计模式变更 |
| 体验优化 | 交互/动画/响应速度改善 |
| 核心重构 | 大规模架构重写；是否升级版本取决于是否新增功能或引入不兼容变更 |
| 技术 | 版本号、依赖、构建配置变更 |
| 文档 | 文档新增/更新 |

## 特殊段落

- **「整体回顾」**：大阶段结束时写总结性回顾，含阶段演进表、关键数据、分类汇总
- **「完整修复历程」**：复杂问题经历多次迭代时，附修复历程表格

## 迁移到新项目的调整项

- 文件变更表中的路径
- 根据项目性质调整分类标题
- 核心框架（双文件、标准 SemVer、时间精确到分钟、加粗关键词格式）直接复用
