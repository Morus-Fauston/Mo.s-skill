# 从讨论与决定到项目规格

这是上游 `to-spec` 的项目化入口。**规格综合由 `to-spec` 承担；本 Skill 负责准备上下文、适配交付位置、记录实质取舍和复核文档一致性。** 需要生成或补全规格时，实际载入并执行上游流程，不能只建议用户另跑一次，也不在这里维护第二套完整规格模板。

## 1. 整理输入与任务边界

读取当前讨论、确认记录、项目指令、领域术语、相关 ADR、现行规格和必要实现。沿用已有上下文与明确决定，不从头采访；把已确认、未决、待调研和已废弃内容分开。

明确用户要的是规格草稿、正式文档更新还是已授权的 issue 交付。已有完整规格且本次只有确定的文案、单条规则或引用修正时，可直接走第 3 步的轻量同步；不要为这种修改重新生成整套规格。

- 纯机械迁移、断链或索引检查使用 `docs-integrity-audit`。
- 尚无可综合的讨论、需要从头选方向时，先回到需求或方案讨论；缺少部分边界则可以先交付带未决标记的规格草稿，不编造答案。
- 先检查工作区，保留已有改动。此入口不修改产品代码、部署、提交或推送；发布 issue 也不等于授权实施。

## 2. 调用上游 to-spec

从当前环境可用的 Skill 目录或用户指定来源定位并读取真实的 `to-spec/SKILL.md` 及必要引用，按其当前正文执行。不要依据名称、旧摘要或本文件记忆上游模板；不要求用户先运行它才继续。

有原生 Skill 调用入口时使用该入口；没有专门调用工具时，在当前上下文读取上游并执行其流程，不虚构工具调用，也不因嵌套使用就另开 Agent 或会话。遵守当前环境的调用权限；不能访问或调用时，如实标明缺少的依赖并交付已整理输入，不悄悄用自写模板冒充上游执行。已可独立完成的轻量同步不受此阻塞。

将以下内容带入上游；同一上下文直接复用，不另造交接文件：

- 用户问题、目标与范围，以及已确认决定和明确非目标；
- 当前领域术语、相关 ADR、现有实现与约束；
- 尚未确认的边界、待调研事实和被否决方案；
- 现有可观察行为、测试入口和已经确认的验证边界；
- 目标文档及本轮写入/发布授权。

执行时保留上游的实质工作：结合仓库理解综合规格、选择能证明外部行为的测试边界、整理用户故事、实现决定、测试决定和非目标。复用已确认的测试边界；新提出且会影响契约的边界给用户确认，不能用“不重新采访”跳过这一决定。未获确认的部分标为提案，不当作现行规则。

### 项目交付适配

本入口默认交付本地项目文档；用户只要草稿时在对话中交付。上游若默认要求发布 issue、设置标签或初始化 tracker，只在本任务明确授权该目标时执行，不为本地规格任务安装工具或要求先配置 tracker。发布已获授权且信息齐全时直接执行，不另加重复确认。

依上游当前模板覆盖本功能实际需要的内容；不能为追求故事数量或填满章节扩展用户范围。规格中的实现决定遵守上游关于代码细节的约束；本入口额外提供的“文档落点链接”仅用于追踪资料，不是强制实现路径。

## 3. 将规格与决定放到正确位置

普通决定简记内容、理由、影响范围和必要例外。**存在实质取舍的决定进入 ADR**：写清采用方案、备选方案最强的支持理由、拒绝依据和接受的代价；可逆性不是唯一门槛。没有真实备选或已知代价时如实说明，不为普通文案和字段细节虚构取舍。

| 内容 | 主要来源 |
| --- | --- |
| 稳定术语、对象定义和领域边界 | 术语表或领域模型 |
| 有实质取舍的产品或架构决定 | ADR；规格引用理由并定义可执行规则 |
| 用户目标、范围和用户故事 | PRD 或现行需求章节 |
| 交互、状态、接口、数据、权限与验收条件 | 设计或技术规格 |
| 阶段顺序、依赖和交付方式 | 开发规划 |
| 可重复执行的操作步骤 | 工作流文档 |

上游产出可作为完整规格，也可映射到项目已有文档，不另造一份竞争的权威规格。尊重用户指定文件与项目模板；落点冲突时只澄清受影响部分。每个规则只有一个主要来源，其他位置链接或摘要；先落主要来源，再更新派生文档和索引。

保留被替代规则的历史追踪，不为整齐重排无关内容。未决或待调研内容不能进入现行规则。决定确认、文档完成、代码实现与验收通过分别记录。

## 4. 复核并交付

核对已确认决定是否遗漏、未决内容是否被误写为定案，以及受影响的术语、旧规则、状态、链接和规格/规划范围是否一致。以项目指定的权威来源和替代关系判断；不能只凭日期或文件类型裁决冲突。只有有歧义的部分暂停，继续无争议工作。

交付时说明：

- 本次实际使用了哪个上游来源，或为何走轻量同步/未能调用；
- 已生成或更新的规格、决定的主要落点与实质取舍 ADR；
- 实际检查、未决边界和仍需用户确认的事项。

默认不另建同步报告，这不限制已获授权的正式文档更新。用户要求保存报告或项目规则指定记录时，沿用项目目录，否则用 `.scratch/reports/decision-to-spec/<YYYY-MM-DD>-<主题>.md`。跨 Agent 或跨会话才补充必要来源、状态和下一步摘要。
