# 人工确认门契约

确认门用于保留用户对产品取舍、正式写入、真实环境和不可逆动作的决定权。它不是所有 Skill 都必须经过的固定流水线，也不是要求每一步都新建文档的流程。各本地 Skill 的 `SKILL.md` 只引用与自身相关的确认门。

## 确认门类型

| 确认门 | 何时使用 | 通过条件 |
| --- | --- | --- |
| `decision` | 产品、架构、交互、范围或方案取舍 | 用户明确选择、批准或否决，并记录理由和边界 |
| `experience` | 原型、视觉、真实交互或人工验收 | 用户在指定环境完成体验并反馈具体结论 |
| `environment` | 真机、沙箱、预发布、云端、生产前条件 | 有对应权限的人确认环境结果和证据 |
| `write` | 正式规格、ADR、验收报告、更新日志或索引写入 | 用户明确允许写入的文件范围和内容类型 |
| `git` | 暂存、提交、推送、发布或关闭远程事项 | 用户明确授权动作和准确路径/资源范围 |

## 等待时的输出

等待确认时必须说明：

- 当前状态：`awaiting-user`；
- 正在等待哪一种确认门；
- 用户需要选择或提供什么；
- 已完成的事实和仍未证明的边界；
- 用户确认后只会执行什么动作。

没有确认时，不得把建议写成决定，不得把原型写成规格，不得把本机结果写成真实环境通过，也不得执行写入或 Git 动作。

## 结束规则

确认完成后只执行确认范围内的动作。确认被拒绝时记录 `rejected` 和原因；信息不足或环境不可用时记录 `blocked`，不要反复追问同一个无法获得的事实。
