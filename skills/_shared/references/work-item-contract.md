# 工作上下文摘要

这不是每次都要填写的表单，也不会自动创建文件。它只在跨 Agent、跨会话，或结果需要长期复用时，帮助 Agent 把工作背景说清楚。

同一个 Agent、同一轮上下文里连续调用多个 Skill 时，直接使用当前对话，不需要填写这份摘要。普通一次性任务也不需要创建工作编号或过程文档。

## 需要传递什么

只有需要跨 Agent 或跨会话继续工作时，才在当前回复、已有报告或正式文档中简要说明：

- 这件事是什么：决策、规格、调研、原型、验证、验收或发布；
- 当前到哪一步：正在处理、等待用户、被阻塞、已完成或已否决；
- 要解决什么问题；
- 已经拿到哪些材料和证据；
- 有哪些限制；
- 还有哪些问题没解决；
- 下一步只做什么。

可以使用自然语言或项目已有的文档格式，不要求 YAML，不要求逐项填空。

## 工作编号

只有确实需要跨 Agent 或跨会话关联时才使用编号：

1. 有 Issue、任务号、阶段号或项目编号时直接复用。
2. 没有外部编号但确实需要关联时，再生成短编号，例如 `WORK-2026-08-23-01`。
3. 单次局部请求不需要编号，也不需要写 `none`。

## 默认不落盘

- 上下文摘要默认写在当前回复里，不因为摘要本身创建独立文件。
- 只有用户明确要求保存、项目规则要求留档，或结果要跨会话长期复用时，才创建文档。
- 只传递与下一步有关的最小事实，不复制整段会话。
- 证据要说明来源、环境、结果、证明了什么和没有证明什么。
- 不得把局部结果扩大成完整规格、阶段通过、用户决定或生产发布。
