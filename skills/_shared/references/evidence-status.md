# 证据与状态契约

本契约把工作进度、单项验证和阶段结论分开，避免把不同层级的状态混在一起。它是维护参考，不是需要用户填写的表单，也不会自动创建过程文件。各本地 Skill 的 `SKILL.md` 保留与自身相关的最小摘要，维护时以本文件为统一参考。

## 工作项状态

用于一次有边界工作的整体进度，尤其是跨 Agent、跨会话或等待用户时：

| 状态 | 含义 |
| --- | --- |
| `proposed` | 已提出，但尚未开始执行或确认范围 |
| `executing` | 当前 Agent、上游 Skill 或项目工具正在处理 |
| `awaiting-user` | 等待用户选择、体验、批准或授权 |
| `blocked` | 缺少关键事实、环境、权限或依赖，无法继续 |
| `completed` | 本 Skill 的完成条件已满足 |
| `rejected` | 用户否决方案、结论或后续动作 |

## 验证项状态

用于单个验证目标或阶段验收项：

| 状态 | 含义 |
| --- | --- |
| `passed` | 必需证据已执行，结果符合通过标准 |
| `failed` | 已执行且证据表明不符合标准 |
| `manual` | 需要用户操作、视觉判断、业务判断或真实环境体验 |
| `blocked` | 缺少关键环境、权限、依赖或凭据 |
| `not-applicable` | 当前范围不涉及该验证层，且已说明原因 |

## 阶段结论

用于一次阶段、版本或里程碑的总体结果：

| 结论 | 含义 |
| --- | --- |
| `passed` | 所有必需验收项通过，没有必需的人工、阻塞或待核实项 |
| `partially-passed` | 核心项通过，但仍有不阻塞的人工、待核实或非必需未完成项 |
| `failed` | 至少一个必需验收项失败，或存在影响核心功能的问题 |
| `blocked` | 缺少关键环境或证据，导致核心验收项无法判断 |

不要把 `manual`、`blocked` 等验证项状态直接写成阶段结论；阶段结论必须结合验收项的必需性和影响范围判断。

## 统一证据记录

```markdown
- 证据：`命令、文件、截图、日志、报告或用户确认`
- 环境：`运行环境、设备、账号角色或版本`
- 结果：`passed | failed | manual | blocked | not-applicable`
- 覆盖：`证明了什么`
- 未覆盖：`没有证明什么`

## 跨 Skill handoff 记录

当一个工作项交给另一个 Skill 继续时，至少传递以下字段。字段可以写在现有报告中，不要求额外创建交接文件：

```markdown
- 来源 Skill：
- 目标 Skill：
- 工作项或改动标识：
- 当前状态：`proposed | executing | awaiting-user | blocked | completed | rejected`
- 已确认目标：
- 已有证据：
- 执行环境：
- 已覆盖：
- 未覆盖：
- 阻塞项：
- 是否需要用户确认：是 / 否；需要确认什么：
- 目标 Skill 的下一步：
```

交接记录只传递目标 Skill 下一步所需的最小事实。上游局部通过不能扩大为阶段通过、正式决定或生产发布；缺失字段应标为“未提供”，不得由下游猜测补齐。
```
